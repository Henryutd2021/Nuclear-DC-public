# Nuclear-DC

Code and data for the paper *Techno-Economic Boundary Analysis of Small Modular
Reactor Cogeneration for Hyperscale Data Center IT and Cooling Loads* by
Honglin Li, Buxin She and Jie Zhang.

The model compares four ways of supplying a 200 MW (nameplate IT) data center
in Houston, Texas, over a full year at hourly resolution:

- Case 0: all electricity bought from the ERCOT day-ahead market, electric (vapor-compression) chillers.
- Case 1: an on-site BWRX-300 (870 MWth, about 316 MWe gross / 300 MWe net) with electric chillers.
- Case 2: the same reactor with steam extracted at the HP-LP crossover to drive a double-effect LiBr-H2O absorption chiller; electric chillers share the cooling dispatch.
- Case 3: an off-grid on-site natural gas combined-cycle plant with electric chillers.

Cases 1 and 2 are solved as mixed-integer programs with Pyomo and Gurobi; Cases
0 and 3 have closed-form dispatch. All cases are compared on total annualized
cost (TAC) and the grid-cost margin relative to Case 0.

## Requirements

- Python 3.10 (the results were produced with 3.10.12 on Linux x86-64)
- Gurobi 11 or newer with a valid license (results produced with Gurobi 13.0.2).
  Gurobi is the only supported solver; the code raises an error if it is
  missing or unlicensed.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`requirements-lock.txt` lists the exact package versions used for the paper.

## Reproducing the results

All model inputs are in `data/`, so no download step is needed. From the
repository root:

```bash
python scripts/run_scenarios.py       # solve all scenarios, write results/
python scripts/analyze_results.py     # paper metrics and checks
python scripts/make_figures.py        # figures/*.pdf
```

or simply `make all`. `run_scenarios.py --plan` prints the scenario count
without solving.

`run_scenarios.py` runs one solve per physical core with one Gurobi thread per
solve. On a 64-core workstation all scenarios finish in under two minutes;
with fewer cores the run time grows roughly in proportion.
Results are written to `results/`, which already contains the outputs used in
the paper. Because the script refuses to overwrite an existing result with a
different configuration, use `--out <dir>` to rerun into a fresh directory and
compare.

### Scenarios

There are 197 scenario records. They reduce to 97 distinct operating
configurations (75 nuclear MILP solves and 22 deterministic grid or gas
cases): records that differ only in reactor or absorber capital cost reuse the
same dispatch, and the capital difference is added as an exact annuity.

- `main_baseline`: the four cases in 2023 with the ATB-Moderate reactor cost.
- `s1_pue` to `s8_size_matching`: the one- and two-way sensitivities (cooling
  efficiency, market year, battery, reactor capital, joint reactor/absorber
  capital, carbon price, WACC, data-center size). Together with the baseline
  these form the 100-record grid in `results/master_kpi_table.csv`.
- `capital_year`: reactor capital of 2,250 and 5,000 $/kWe in other market years.
- `ptc40_*`: Cases 1 and 2 of the 100-record grid with the production tax
  credit levelized over 40 instead of 20 years.
- `flat_load`: a constant IT load with the same annual energy.
- `biennial`, `biennial_no_outage`: the second year of a two-year refueling
  cycle, keeping background outages or dropping all outages (upper bound).
- `nuclear_carbon_exempt`: carbon prices of 50 and 100 $/t with nuclear
  lifecycle emissions not billed.
- `willans_slope`: Case 2 with extraction penalties of 0.08 to 0.25 MWe/MWth.

### Outputs

Each record has a folder `results/<group>/<run_id>/` with

- `summary.json`: annual costs, energy flows, emissions, water use and run metadata
- `config.json`: the full parameter set used for the run
- `dispatch.csv.gz`: the hourly dispatch (a relative symbolic link when the
  dispatch is shared with another record; on Windows clone with
  `git clone -c core.symlinks=true` so the links are kept)

The tables in `results/` collect these records:

- `all_records.csv`: all 197 records
- `master_kpi_table.csv`: the 100-record grid, with grid-cost margins
- `paper_ledger.csv`: the grid plus the `capital_year` records
- `ptc40_ledger.csv`: the 40-year credit records with matched Case 0/3 controls
- `paper_metrics.json`: derived quantities reported in the paper (crossover
  carbon prices, capital parity, value decomposition, sensitivity spans, ...)
- `value_decomp_case2.csv`: decomposition of the Case 2 minus Case 1 cost difference
- `verification.json`: cost-identity and solver-gap checks
- `manifest.json`: scenario list, software versions and wall time

`figures/` contains Figures 2-6 and Supplementary Figures S1-S2 of the paper.
Figure 1 is a schematic and is not generated by code. The figures use the
Arial font; matplotlib substitutes another font if Arial is not installed.

## Repository layout

```text
config/      case definitions, solver settings and the S5 capital grid
data/        hourly model inputs, cost scenarios and the scripts that built them
src/         model code (cases, MILP builder, KPIs, scenario definitions)
scripts/     run, analysis and figure entry points
notebooks/   figure notebook and plotting helpers
results/     run-level results and summary tables
figures/     paper figures (PDF)
tests/       pytest suite (python -m pytest)
```

## Data

The hourly inputs and their sources are described in `data/README.md`. In
short: ERCOT day-ahead prices (ERCOT market information system, via
gridstatus), hourly carbon intensity derived from the EIA-930 generation mix
and UNECE lifecycle emission factors, Houston weather from Open-Meteo (ERA5
reanalysis, CC BY 4.0), Henry Hub gas prices from EIA, and the IT load profile
derived from the NLR generative-AI workload dataset (Vercellino et al., 2026,
doi:10.7799/3025227). The scripts in `data/_raw/` re-download and rebuild these
files; `make data` runs them.
